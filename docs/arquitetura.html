1. Visão geral

O AquaAccess Facial é uma aplicação desktop offline-first para controle de acesso às piscinas de um clube. O fluxo principal cobre:

  1. Cadastro de associados (chamados de pacientes na UI e no banco)
  2. Registro e validade de exames médicos
  3. Liberação ou negação de acesso à catraca/piscina
  4. Integração em rede com o videoporteiro Intelbras XPE 3200 PLUS IP

Não há backend remoto obrigatório: tudo roda localmente no PC do clube. A tela de sincronização com nuvem (Supabase) existe na UI, mas ainda é placeholder.

4. Arquitetura Electron

┌─────────────────────────────────────────────────────┐ │ Processo Principal (main.js) │ │ ├─ db.js → domínio / SQLite │ │ ├─ xpeBridge.js → HTTP ← XPE │ │ ├─ xpeSetup.js → descoberta / assistente │ │ └─ xpeAutomation/ → Playwright → painel web XPE │ ├─────────────────────────────────────────────────────┤ │ preload.js → window.clubAccess.* │ ├─────────────────────────────────────────────────────┤ │ Renderer: login → medico | admin │ └─────────────────────────────────────────────────────┘

Segurança: contextIsolation: true, nodeIntegration: false. Comunicação apenas via IPC.

Padrão para feature nova: db.js → main.js (IPC) → preload.js → renderer.

5. Fluxo desde a abertura

  1. Usuário executa npm start ou o instalador.
  2. app.whenReady: initDb(), auto-discover XPE, bridge HTTP.
  3. createWindow() abre renderer/login/login.html.
  4. Login via window.clubAccess.login → authenticateUser.
  5. Sessão em sessionStorage (clubAccessRole, usuário, nome).
  6. Redireciona: admin → admin/home.html; médico → medico/medico.html.

6. Autenticação e perfis

  • Hash bcrypt; checagem de usuário ativo.
  • Roles: apenas admin ou medico.
  • Admin pode entrar na aba médico; médico não entra como admin.
  • Não há JWT — sessão só no renderer.
Funções de CRUD de usuários do sistema existem em db.js (createSystemUser, etc.), mas ainda não estão no preload/IPC/UI.

Atenção: hoje não há autorização por role no IPC. Qualquer renderer autenticado pode chamar as APIs do preload.

7. Banco de dados

Engine sql.js. Cada escrita chama persist() e grava club-piscinas.db.

TabelaConteúdo

O patients.id é o mesmo número usado como ID Usuário no XPE.

8. Cadastro de associados

Fluxo principal no painel médico:

  1. Nome, telefone (obrigatório), CPF (opcional).
  2. Foto obrigatória (arquivo ou câmera).
  3. patientsCreate → createPatient → grava foto em patient-photos/.

No domínio: associados do clube = patients; operadores do app = users.

9. Regras de negócio

Centro de verdade: db.js.

Liberação — registerPoolAccess

Concede acesso se:

  1. Paciente existe
  2. Não está blocked
  3. Tem exame Válido com valid_until ≥ hoje (inclui “vence nesta semana”)

Caso contrário, nega. Sempre grava em access_events.

Exame — createExam

  • Validade = data do exame + N dias (configurável; padrão 30)
  • Alinha a dias da semana permitidos
  • Exames vigentes anteriores → Substituído; novo → Válido

10. Integração Intelbras XPE

  1. XPE envia evento HTTP para o PC (ex.: porta 37891, path /intelbras/xpe).
  2. Bridge extrai userId ou CPF.
  3. findPatientIdForXpeBridge resolve o paciente.
  4. Chama a mesma registerPoolAccess.
  5. Se liberado e OpenDoor ativo → HTTP OpenDoor no equipamento.

Exportação de fotos/CSV e sync Playwright ficam em Dispositivo facial (admin). Ajuste de seletores: xpeAutomation/selectors.js.

12. Como adicionar um novo módulo

  1. Funções em db.js e export.
  2. ipcMain.handle em main.js.
  3. Expor em preload.js (window.clubAccess).
  4. Admin: view HTML + VIEW_FILES + nav + lógica em admin.js.
  5. Médico: seções em medico.html + medico.js.
  6. Integração externa: módulo no main (como xpeBridge.js).

Não acessar Node/filesystem/banco direto no renderer.
